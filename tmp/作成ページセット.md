# 作成ページセット（依頼用）

このファイルだけ渡せば、1記事分の提出物が作れる。  
公開サイトは **AYATORI 使い方**（`https://help.ayatori-inc.co.jp/`）。営業 LP ではない。現場で「じゃあどうやるんスか」に答える短い手順である。

提出は **HTML**（ブラウザで確認しやすい）。公開リポジトリの正本は Markdown。マージ（英文化・`.md` 化・左メニュー登録）は受け取り側の仕事。

---

## 作業の流れ（画像は先置き）

手順の文章を書く人と、スクショを撮る人が分かれてよい。AI が先に枠を置き、人はファイル名どおりに画像を落とす。

1. **AI（または執筆）** — 本文の HTML を書く。操作の区切りや「ここは画面があったほうがよい」箇所に、あらかじめ `<img>` を置く。ファイル名まで決める。
2. **提案** — AI は「こことここに画像があるとよい」と一覧でも示す（何を撮るか・推奨ファイル名）。
3. **人** — 画面を撮り、そのファイル名で `_images/` に置く。HTML は触らなくてよい。
4. **確認** — `index.html` をブラウザで開く。画像が出れば OK。欠けていればファイル名か置き場を直す。

画像がまだ無くても HTML は先に提出してよい。枠だけ残し、後から `_images/` を足す。

## 提出するもの（1記事＝1フォルダ）

受け取りは **フォルダごと**。バラバラの単ファイルではなく、下のまとまりのまま渡す。

```
（フォルダ名）/
  index.html      本文（ブラウザで開いて読めること）
  _images/        この記事専用の画像（枠だけ先に書いて、後から置いてよい）
```

- **フォルダ名**は提出時、日本語でもよい（例: `在宅の日`）。受け取り側が英小文字スラッグに変える。
- フォルダ直下に `index.html` と `_images` 以外を増やさない（CSS・JS・別 HTML は不要）。
- 1フォルダ＝1仕事。複数仕事を1枚に詰めない。
- `_images/` は最初から作っておく。中身は後からでよい。
### 複数記事になるとき

記事が複数にまたがる場合も、**記事フォルダを並べてまとめて渡す**。ZIP でも親フォルダでもよい。

```
提出セット/
  在宅の日/
    index.html
    _images/
  日報を書く/
    index.html
    _images/
```

**フォルダをまたぐ参照は、相対パスでちゃんと書く。**  
絶対パス（`C:\...`）や、自分の PC だけにある場所、外部アップローダの URL は使わない。受け取り側がフォルダごと動かしてもリンクが切れないこと。

| 参照先 | 書き方の例 |
|--------|------------|
| 同じ記事の画像 | `./_images/01-example.webp` |
| 隣の記事へ | `../日報を書く/index.html` |
| 隣の記事の画像（原則避ける。その記事の `_images/` に置く） | — |

公開後のパス（`/jobs/.../` など）が分かっているなら、それも併記してよい。まだ無い・名前が仮のときは、相対パスを正とし、コメントで「想定の公開パス」を残す。

## index.html の書き方

見た目の装飾は不要。見出しと段落・リスト・画像枠があれば足りる。  
ブラウザで `index.html` を開いて確認する（画像は後から置いてもよい）。
### 先頭に書くメタ（必須）

`<title>` のほか、本文の直前に次を書いておく（コメントでも表でも可）。

| 項目 | 例 | メモ |
|------|----|------|
| タイトル | 在宅の日、何をすればいいか | 現場の言葉。製品名だけで名指ししない |
| 説明 | 在宅の日に、学習と日報のどちらを先に見るか。 | 1文 |
| 対象読者 | 指導員 / 利用者 / 共通 のいずれか | 記事の先頭で誰向けか分かるように |
| 想定の置き場 | よくある仕事 / StudySphere / DailyReportHub / おしごとコネクト / 共通 | 迷ったら「よくある仕事」 |

文書番号・版・施行日は受け取り側が振る。提出側は書かなくてよい。

### 本文の三段（必須）

見出しはこの3つで揃える。

1. **判断** — こういうときはこうする（3〜7行）。規程の代わりにしない。指定基準・加算の「正解」は断定しない。
2. **操作** — この画面でこれを押す。番号付き手順＋必要なスクショ。
3. **詰まったら** — よくある失敗と、問い合わせる前に見ること。

冒頭の「判断は貴事業所の規程が優先…」は公開側のレイアウトが出すので、**本文に書かない**。

### 最小の HTML 骨格（コピー可）

操作のあいだと終わりに、画像枠を先に書く。コメントで「何を撮るか」を残すと、撮る人が迷わない。

```html
<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <title>在宅の日、何をすればいいか</title>
  <meta name="description" content="在宅の日に、学習と日報のどちらを先に見るか。">
</head>
<body>

<!-- 対象: 指導員 / 想定の置き場: よくある仕事 -->
<!--
  画像の置き場（先置き）:
  - 01-top-menu.webp … 手順1のあと。トップのメニュー全体
  - 02-confirm.webp  … 操作の最後。確認ボタン付近
-->

<h1>在宅の日、何をすればいいか</h1>

<h2>判断</h2>
<p>（3〜7行。推奨のやり方として書く。断定しない。）</p>

<h2>操作</h2>
<ol>
  <li>…（画面を開く）</li>
</ol>
<!-- 撮るもの: トップのメニュー全体 -->
<p><img src="./_images/01-top-menu.webp" alt="トップのメニュー"></p>
<ol start="2">
  <li>…（確認する）</li>
</ol>
<!-- 撮るもの: 確認ボタン付近 -->
<p><img src="./_images/02-confirm.webp" alt="確認ボタン"></p>

<h2>詰まったら</h2>
<ul>
  <li>…</li>
</ul>

</body>
</html>
```

## 画像（`_images/`）

### AI 向け（枠を先に書く）

- 操作手順を書いたら、「ここは画面があったほうがよい」箇所に `<img>` を先置きする。人が後から撮る前提でよい。
- 置きどころの目安: 操作の区切りのあいだ、押すボタンの直後、手順の最後。判断の長文には無理に付けない。
- ファイル名まで決める。推奨は `番号-内容.拡張子`（例: `01-top-menu.webp`）。HTML 先頭か画像の直上に、撮る内容をコメントで残す。
- 提出時に「画像一覧」（ファイル名 → 何を撮るか）を短く添えるとよい。

### 撮る人向け（ファイルを置くだけ）

- 置き場はこの記事フォルダ内の `_images/` だけ。外部 URL や別フォルダに置かない。
- HTML に書いてあるファイル名と**一字一句同じ**にする。置けたらブラウザで `index.html` を開き直す。
- 形式は WebP / PNG / JPG いずれでも可。見切れ・黒帯より、操作箇所が分かること優先。
- **個人情報・実名の利用者・実在事業所が分かる画面は写さない。** 必要ならモザイクか架空データにする。
- `alt` は HTML 側に既にある。撮る人は画像ファイルだけ用意すればよい。

## リンクのルール（重要）

このサイト（およびこのリポジトリで公開するページ）以外へ、手順の本体を逃がさない。

| してよい | しない |
|----------|--------|
| 同じ提出セット内の相対パス（画像・隣の記事） | `C:\Users\...` やデスクトップ直指定、外部のスクショホスト |
| 公開済みの使い方ページへのパス（下表） | 会社サイト本体の `/help/` や営業 LP への誘導を手順の正にする |
| 製品そのもののログイン URL など、操作に必須の公式入口 | 「詳しくは別サイトの長いマニュアルへ」で本編を空にする |

複数ファイルにまたがるときも、提出セットの中だけで辿れる **相対パス** にしておく。フォルダごと受け取る前提である。

公開サイト上のパスは、根から書いて末尾スラッシュ付き（例: `/jobs/remote-day/`）。  
まだ無いページへリンクするときは、提出セット内の相対パスを書き、必要なら **想定の公開パスをコメントで残す**（受け取り側が繋ぐ）。
よく使う公開パス:

| パス | 中身 |
|------|------|
| `/` | このサイトの読み方 |
| `/jobs/` | よくある仕事 |
| `/studysphere/` | StudySphere |
| `/dailyreporthub/` | DailyReportHub |
| `/jobconnect/` | おしごとコネクト |
| `/common/` | ログイン・問い合わせ・Discord など横断 |
| `/common/contact/` | 問い合わせ |
| `/common/discord/` | Discord の使い方 |
| `/common/discord-signup/` | Discord のアカウントを作る |

本番のドメインは `https://help.ayatori-inc.co.jp`。HTML 内ではドメイン無しのパス（`/common/contact/`）で書いてよい。

## 載せる／載せない

### 載せる

- 1ページで閉じる手順（判断 → 操作 → 詰まったら）
- 画面名と押す場所（必要な範囲）
- 現場用語（例: 「本日有効」「今日のパスワード」）
- 詰まったときの切り分け（問い合わせる前に見ること）

### 載せない

- 価格・資料請求・機能訴求（営業の仕事）
- 社内向けの基礎学習の本文（「コースへ」と触れる程度まで）
- 行政通知の正式解釈の断定
- ヒーロー演出・装飾用の大きなバナー・無関係な動画埋め込みの多用
- 別 CSS / 別 JS / フォント CDN（提出セットに含めない）

## 部屋の目安（どれ用か迷ったら）

| 想定の置き場 | 向いている記事 |
|--------------|----------------|
| よくある仕事 | 「在宅の日どうするか」「日報を書く」など、職員が開く仕事そのもの |
| StudySphere | 学習・パスワード・アプリなど、製品操作の詳細 |
| DailyReportHub | 日報・勤怠・ケース記録など、製品操作の詳細 |
| おしごとコネクト | 実習マッチング・アカウント・担当のひもづけ |
| 共通 | Discord・問い合わせ・アカウントなど製品横断 |
| 利用者さま向け | 本人が画面でやること（スタッフさんが URL を渡す） |

職員に渡す入口はできるだけ **よくある仕事**。製品の細かい操作は各製品部屋へリンクする、が基本。

## 提出前チェック（短く）

1. 記事はフォルダごと。直下に `index.html`、画像は `_images/`。
2. 本文が **判断 / 操作 / 詰まったら** の三段になっている。
3. 画像枠が先置きされ、ファイル名どおりに `_images/` へ置けばブラウザで見える。
4. 画像・記事間リンクが相対パス。PC の絶対パスや外部ホストを指していない。
5. 公開パスが分かるものは `/部屋/.../` も併記（または「想定パス」コメント）。
6. 個人情報・実名利用者が写っていない。
7. 営業文・基礎学習の長文が入っていない。

---

## 受け取り側がやること（提出者は知らなくてよい）

- フォルダ名を英小文字スラッグへ変更し、`src/content/docs/<部屋>/<slug>/` へ配置
- `index.html` を `index.md`（必要なら `.mdx`）へ移し、frontmatter・文書番号を付与
- 画像パスを Markdown 記法へ合わせる
- `astro.config.mjs` の左メニューへ登録
- ビルドして公開

提出者は **ブラウザで確認できる `index.html` と `_images/`** までで完了とする。
