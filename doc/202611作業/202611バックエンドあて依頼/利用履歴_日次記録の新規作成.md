# 利用履歴からの日次記録の新規作成

フロントエンドの利用履歴画面（`/instructor/home-support/history`）に「新規作成」を置いた。利用者がその日の記録をまだ持っていないとき、指導員が利用者を選ぶと、あとから本人が編集できる下書きの日次記録を1件作る。

呼び出し元は `src/utils/api.js` の `createHomeSupportDailyRecord`。次のリクエストを送る。

```http
POST /api/remote-support/daily-records
Authorization: Bearer <既存の指導員トークン>
Content-Type: application/json

{
  "userId": "123",
  "date": "2026-11-19"
}
```

`userId` は画面の選択値なので、文字列で届くことがある。数値に直して扱う。`date` は `YYYY-MM-DD`。

## 作るレコード

テーブルは `remote_support_daily_records`。入れる値は次だけにする。

| カラム | 値 | 理由 |
|---|---|---|
| `user_id` | リクエストの利用者ID | |
| `date` | リクエストの日付 | 利用履歴で選んでいる日 |
| `condition` | `普通` | NOT NULL。良い・普通・悪いのいずれかが必須 |
| `work_note` | `作成　要編集` | NOT NULL。本人記録の作業予定。全角スペースを含むこの文字列のまま保存する |

打刻（`mark_start`、`mark_lunch_start`、`mark_lunch_end`、`mark_end`）、体温、睡眠時間、体調備考、作業実績、日報、支援方法、支援内容、助言、指導員コメント、記録者名、写真は入れない。いずれも任意項目なので、未設定のままにする。

対象は在宅利用者に限る。`user_accounts` で `role = 1`、`status = 1`、`is_remote_user = 1` であることを確認し、それ以外は作らない。

`unique_daily_record`（`user_id` と `date`）にすでに行があるときは作らない。

## 応答

成功:

```json
{ "success": true, "data": { "id": 1 } }
```

失敗は `{ "success": false, "message": "日本語のメッセージ" }`。画面は `message` をそのまま出す。

| 状態 | HTTP | message |
|---|---|---|
| 利用者または日付がない、日付の形式が違う | 400 | 利用者と日付は必須です |
| 在宅利用者が見つからない | 404 | 在宅利用者が見つかりません |
| 同じ利用者・同じ日の記録が既にある | 409 | この日の記録は既にあります |

## 既存APIとの関係

同じパスに、週次評価用の一覧取得がある。

```http
GET /api/remote-support/daily-records?userId=&startDate=&endDate=
```

これは `routes/remoteSupportRoutes.js` に実装済み。GET の挙動は変えない。今回追加するのは POST だけ。

認証は、この一覧取得や日次勤怠APIと同じトークン検証にする。
