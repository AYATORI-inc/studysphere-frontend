# 本番サーバーのタイムゾーン確認

確認は 2026-11-19 に完了した。結論は `doc/時間の取り扱い.md` に残してある。ホストは日本時間、Node と MySQL のコンテナは UTC。このファイルの手順は、同じ確認をやり直すときの記録。

在宅の打刻時刻が、入力した時刻と違う時刻で画面に出ている。原因を切り分けるため、本番サーバーへ SSH で入り、時刻の設定を確認してほしい。設定の変更はしない。見るだけ。

2026-10-28 の作業メモでは、VM 本体のタイムゾーンは `Asia/Tokyo` だった。アプリと MySQL は Docker コンテナの中で動いている。コンテナ側には `TZ` が渡されていない。公式イメージの初期値は UTC なので、ホストが日本時間でも、中の Node と MySQL は UTC のままのことがある。ここを実機で見てほしい。

## 接続

- SSH: `studysphere-backendssh.ayatori-inc.co.jp`
- 配置先: `/opt/studysphere`
- コンテナ名: `studysphere_backend`（Node）、`studysphere_mysql`（MySQL）

`.env.production` の中身、パスワード、秘密鍵は返さない。

## 1. ホスト

```bash
date
timedatectl
cat /etc/timezone
ls -l /etc/localtime
```

`Time zone:` の行と、`date` の出力をそのまま返す。

## 2. バックエンドコンテナ

```bash
docker exec studysphere_backend date
docker exec studysphere_backend printenv TZ
docker exec studysphere_backend node -e "console.log(JSON.stringify({tz:process.env.TZ||null,offsetMin:new Date().getTimezoneOffset(),iso:new Date().toISOString(),local:new Date().toString()}))"
```

`printenv TZ` が空なら、その旨を書く。`offsetMin` は、日本時間なら `-540`、UTC なら `0` になる。

権限で失敗する場合は、先頭に `sudo` を付けて同じコマンドを実行する。

## 3. MySQL コンテナ

```bash
docker exec studysphere_mysql date
docker exec studysphere_mysql printenv TZ
docker exec studysphere_mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -N -e "SELECT @@global.time_zone, @@session.time_zone, NOW(), UTC_TIMESTAMP();"'
```

パスワードはコンテナ内の環境変数を使う。コマンドの出力にパスワードは出ない。4列の結果をそのまま返す。

`NOW()` と `UTC_TIMESTAMP()` の差が、セッションのタイムゾーンになる。日本時間なら 9 時間、UTC なら同じ時刻になる。

## 4. 保存されている打刻

画面に出ている時刻ではなく、テーブルに入っている数字が知りたい。`CONVERT_TZ` は使わない。

```bash
docker exec studysphere_mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" curriculum-portal -e "SELECT id, user_id, date, mark_start, mark_end, mark_lunch_start, mark_lunch_end FROM remote_support_daily_records WHERE mark_start IS NOT NULL ORDER BY id DESC LIMIT 5;"'
```

直近5件の、この列の値を返す。利用者名は不要。

比較の目安は、指導員が 10:00 開始、15:00 終了、休憩 12:00、休憩終了 13:00 と入れた記録。データベースの `DATETIME` は UTC の時計で保存する想定なので、その記録なら `mark_start` は `01:00:00`、`mark_end` は `06:00:00`、`mark_lunch_start` は `03:00:00`、`mark_lunch_end` は `04:00:00` になっているはず。実際の数字がこれと違う場合は、その数字をそのまま返す。

## 返してほしいもの

1. ホストの `date` と `timedatectl` の `Time zone`
2. バックエンドコンテナの `date`、`TZ`、`offsetMin`、`local`
3. MySQL コンテナの `date`、`TZ`、`@@global.time_zone`、`@@session.time_zone`、`NOW()`、`UTC_TIMESTAMP()`
4. 直近の打刻5件の `DATETIME` の数字

値の変更、コンテナの再作成、`TZ` の追加は、この確認が戻ってから別途依頼する。
