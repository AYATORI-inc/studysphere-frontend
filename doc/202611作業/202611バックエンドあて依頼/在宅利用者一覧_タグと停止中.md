# 在宅利用者一覧に、タグと停止中を足す

対応済み。在宅利用者情報は、通常は稼働中だけを取得する。チェック「停止中もふくめて表示」のときだけ `includeInactive=1` を付ける。名前の下に `tags` を出し、タグ検索はその配列を見る。稼働状態の文言は出さない。

在宅利用者情報（`/instructor/home-support/users`）で、利用者のタグを表示してタグ検索する。稼働中・停止中の表示はしない。チェック「停止中もふくめて表示」が付いたときだけ、停止中の在宅利用者も一覧に含める。

画面は次を呼ぶ。`includeInactive` が無いときは、今までどおり稼働中だけ。

```http
GET /api/users/satellite/:satelliteId/home-support-users-list?includeInactive=1
Authorization: Bearer <既存の指導員トークン>
```

`instructorIds` があるときの条件は、今のまま先にかける。

## 今の動き

`scripts/userController.js` の `getSatelliteHomeSupportUsers` は `ua.status = 1` で切っている。`user_tags` も `ua.status` も返していない。停止中（`status = 0`）は、クエリを足しても出てこない。

## 変えること

`getSatelliteHomeSupportUsers` だけ。

`user_tags` を利用者ごとにまとめ、`tags` として返す。タグが無ければ `[]`。`ua.status` も返す。`1` が稼働中、`0` が停止中。

`includeInactive=1` のときは `ua.status IN (0, 1)`。それ以外は今どおり `ua.status = 1`。`is_remote_user = 1` と拠点の条件は、どちらも今のまま。

各利用者は次の形。今ある項目は残す。

```json
{
  "id": 44,
  "name": "利用者名",
  "login_code": "...",
  "status": 1,
  "is_remote_user": true,
  "instructor_id": 3,
  "instructor_name": "指導員名",
  "company_id": 1,
  "company_name": "企業名",
  "tags": ["在宅支援", "午前"]
}
```

在宅支援の解除（`PUT /api/users/:userId/remove-home-support`）は変えない。

## 確認

`includeInactive` なしでは、稼働中の在宅利用者だけが返り、各人に `tags` と `status` がある。`includeInactive=1` では、停止中の在宅利用者も同じ形で加わる。通所だけの利用者は、どちらの場合も入らない。
